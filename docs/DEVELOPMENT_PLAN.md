# TaiPlan 鸿蒙版三阶段开发计划与进度台账

本计划用于把现有 TaiPlan Harmony 0.5.0 扩展为兼具待办、日历、快速收集和智能辅助的鸿蒙原生应用。后续开发合并为三个较大的交付阶段：第一阶段交付完整的任务与日历体验；第二阶段交付语音、系统提醒和 AI；第三阶段交付专注与习惯工具，并完成产品验收。

阶段压缩意味着每次交付包含更多完整能力。每阶段内部仍按照数据、业务、界面、设备验收的顺序完成小检查点。执行者必须完成一个可运行的检查点再继续，避免同时修改全部模块后无法定位故障。

计划制定日期为 2026 年 10 月 10 日。当前功能基线为 0.5.0。以下全部新增工作均为待开发，不代表已经实现。执行本计划的 AI 必须结合 PROGRESS.md 中的实时状态继续工作。

## 3 产品行为统一约定

以下规则用于减少执行者自行猜测。若后续用户明确改动，应更新规则和对应验收用例。

### 3 1 页面分工

今天页面显示今日任务完成概览、需要关注的事项、接下来有时间的安排、今天未指定时间的任务。已完成默认收起。清单筛选不应改变今天统计。

待办页面承担收集箱、已安排任务、清单分类和已完成记录。默认进入收集箱或用户选择的上次位置。筛选、排序和批量操作进入面板，不把所有控件永久放在顶部。

日历页面承载年、月、周、日视图。年视图从年份入口进入，月周日通过紧凑切换器选择。日历与待办共享同一业务数据，不建立第二套任务副本。

设置页面提供外观、显示与操作偏好、日历偏好、提醒、语音与 AI、功能模块、数据与导入导出、帮助与版本信息。

全局添加入口位于底部导航上方的易触及区域。文案为“记一件事”，同时显示加号。设置页可以保留相同入口或在页面功能不适用时隐藏，但必须记录一致的规则。搜索入口可从今天和待办进入同一个搜索页，其他页面通过该搜索页导航到结果。

### 3 2 快速收集与完整编辑

快速面板第一次打开只要求标题。输入一句话即可保存为无日期任务，不强制选择时间、标签和优先级。无日期任务进入收集箱，保存后立即给出“已记到收集箱”和“安排今天”动作。

快速面板包含文字输入、麦克风按钮、解析后的可选日期标签和保存按钮。详细设置通过“更多”进入。输入法自带语音仍可直接向文字框输入。

从日历长按时间格创建，使用选中的时间段作为默认安排，并显示可清除的预填项。从今天使用快速入口，默认仍允许收集；如果用户明确选择“安排今天”，才设置计划日期。

完整编辑支持标题、类型、计划日期、起止时间、截止期限、地点、备注、清单、标签、优先级、重复、提醒和子任务。默认显示常用项，重复和提醒等高级项可以折叠。未保存内容在意外关闭前应能恢复或提示。

### 3 3 时间类型

| 用户输入 | 保存状态 | 展示方式 | 逾期判断 |
| --- | --- | --- | --- |
| 买一本书 | 无安排的任务 | 收集箱 | 没有截止则不逾期 |
| 今天看一章书 | 仅安排日期的任务 | 今天与日历顶部无时间区 | 没有截止则不逾期 |
| 明晚七点到八点看书 | 有起止时间的任务 | 日历时间块与今天安排 | 只有明确截止才按任务截止判断 |
| 周五之前交报告 | 有截止的任务 | 待办 截止提示 | 按用户指定截止判断 |
| 国庆节 | 全天事件 | 日期顶部全天区 | 不按待办逾期 |
| 明天三点开会 | 有时间的事件 | 日历时间块 | 过时显示已结束，不自动称为未完成 |

计划时间、截止时间、提醒时间分别保存。没有截止期限的任务到晚上不应自动染红。高优先级和逾期是两个状态；高优先级不等于已经逾期。

事件默认不需要勾选完成。任务支持完成与取消完成。今天“任务完成比例”只统计今天计划的任务发生项；事件数量作为安排信息单独显示。收集箱中高优先级任务可出现在“需要关注”区，但不进入今日任务分母。

无时间任务放在日历顶部。全天事件与无时间任务使用明确的小标题区分，避免把生日和待办当成同一种对象。

### 3 4 视觉与交互

- 主色系为白、黑、灰。深色背景采用有层次的深灰，具体颜色以设备截图验证。
- 移除红色卡片描边。红色仅用于小型高优先级标记、真实逾期和必要的破坏性操作提示。
- 分类颜色用于标签与日历区块，同一分类跨视图保持一致。颜色必须配文字，不作为唯一信息。
- 普通卡片保持稳定底色。沉浸式材质优先用于导航、浮动操作和弹出面板。
- 添加、完成、菜单等操作区域建议至少 48vp。该数值是本项目内部设计目标，不宣称是所有鸿蒙控件的强制规则。
- 卡片第一行是完成操作和标题；第二行仅显示必要的时间与分类信息；长备注进入详情。
- 普通列表标题过长允许合理换行，重要内容不能完全依赖省略号。
- 删除明确反馈并提供撤销。保存失败保留输入内容和具体原因。
- 键盘出现时输入与保存按钮可见；关闭面板时键盘状态正确恢复。
- 滚动、拖拽、左右切换月份和底部导航不得互相抢手势。
- 内部验收目标包括普通正文对比度达到 4.5:1，开启大字体后主要按钮仍可访问。

### 3 5 功能开关

首次使用启用任务、日历和基本搜索。AI、专注、习惯和倒数日是可选模块。用户可以选择“简洁”和“完整”的预设，再逐个调整模块。

开关描述区分“隐藏入口”和“停止后台提醒”。隐藏入口不删除数据，也不隐式取消提醒。停止提醒需要说明影响范围并执行相应取消。关闭 AI 不影响已有任务，关闭语音仍可文字输入。

模块隐藏后，设置仍能重新启用；搜索结果可提示数据属于已隐藏模块，并提供查看入口。底部始终保持今天、待办、日历、设置四个核心栏目。

## 4 数据结构与迁移先于界面扩展

### 4 1 保留与新增字段

保留既有任务 ID、创建时间、更新日期、标签、子任务和完成记录。第一阶段新增明确的数据模型；下列是语义契约，最终 ArkTS 声明必须符合本机编译器，不直接照搬不兼容的 TypeScript 写法。

| 对象 | 字段或内容 | 约束 |
| --- | --- | --- |
| Task | kind | task 或 event |
| Task | scheduleMode | unscheduled date timed allDay |
| Task | plannedDate | 本地日期 YYYY-MM-DD，仅日期安排使用 |
| Task | startAt endAt timeZone | 有时间的事件或任务，结束晚于开始 |
| Task | deadlineMode deadlineDate deadlineAt | none date datetime 三种明确截止方式 |
| Task | location | 独立地点文本，可为空 |
| Task | categoryId listId | 分类与清单关联，可为空 |
| Task | sourceType sourceRef | 手动 离线解析 AI ICS 桌面导入等来源 |
| RecurrenceRule | frequency interval weekdays monthDays months | 结构化规则，禁止只用自由字符串 |
| RecurrenceRule | untilDate count | 可不设结束；日期结束与次数结束互斥 |
| OccurrenceOverride | seriesId originalKey | 指向原计划发生项的稳定身份 |
| OccurrenceOverride | changedFields cancelled | 只修改一次的字段与取消状态 |
| ReminderSpec | anchor offset absoluteAt enabled | 相对计划开始 相对截止 或独立时刻 |
| ReminderLink | logicalKey provider systemId state | 系统登记与业务提醒之间的映射 |
| ImportSource | sourceId UID recurrenceId sequence contentHash | 导入去重 更新对比和来源追踪 |
| AppSettings | schemaVersion 和用户偏好 | 不把密钥放进普通设置备份 |

unscheduled 不带安排日期；date 只安排一天且不占小时区块；timed 必须有起止时间；allDay 使用日期范围，结束日期按排他端点表示。Task 与 event 的允许组合在校验服务中统一限制。

有时长但尚未安排的任务可以保留预计用时，不因此自动获得开始时间。跨午夜日程必须能保存，并按日期拆分显示，原始事件仍然是同一条记录。

日期不是 UTC 午夜时间戳。仅日期值使用 YYYY-MM-DD；具体时刻使用时间戳并保留时区语义。浮动本地事件与指定时区事件不能混为一类。

### 4 2 建议新增存储

新增关联表承载计划、重复规则、单次覆盖、提醒映射和导入来源。表名可采用 task_schedule、task_recurrence、task_occurrence_overrides、reminder_links、import_sources、categories 和 task_lists。

对已有 tasks、task_options、task_occurrences、task_details、task_step_states 保持兼容。新增数据库 schema_version；它与应用版本号、JSON 备份格式版本是三种不同版本。

建议新增 MigrationService 负责有序迁移；TaskRepository 调用它，不再持续扩大 load 内的迁移分支。每个 ResultSet 都关闭，SQL 使用参数绑定，批量更新保留事务。

### 4 3 从 0.5.0 升级的明确映射

1. 旧 dueAt 为 0：迁为无安排任务，保留完成状态和预计用时。
2. 旧 dueAt 大于 0、startMinute 为 -1：迁为日期任务，计划日期从旧日期提取。旧字段原本承担截止含义，迁移时保留其截止语义，不能自动清空使逾期消失。
3. 旧 dueAt 大于 0、startMinute 非负：从旧本地日期和开始分钟还原起止时间；旧的结束时间逾期行为通过兼容截止字段保留。
4. 给兼容迁移记录写入 legacyTimeSemantics 标记。在详情中解释“来自旧版本的截止设置”，用户后续可改成纯安排。
5. 新建任务按第 3 节语义处理：只有日期安排时不自动产生截止。
6. 旧 daily weekly monthly 迁为结构化规则。每周保留起始星期，每月保留原版不足日期取月末的行为。
7. 旧日期完成、跳过与子任务进度映射到原始发生日期，不重置历史状态。
8. 每一步迁移与其完成标记在同一事务内。失败回滚并保留旧表，不写“迁移完成”。
9. 重启再次迁移不得重复添加数据。用旧版真实结构的测试库验证至少两次启动。
10. 升级失败时明确提示，并提供保存诊断与重新尝试入口；禁止恢复空数据库来假装成功。

### 4 4 重复发生项的身份

发生项身份由系列 ID 和原计划发生日期时间组成，不能用改期后的日期作为唯一键。原定周一、单次移到周三，仍对应同一个原始发生项。

只修改这一次：写 override，系列规则保持原样。修改这一次及以后：分割系列，前段结束在原始边界之前，后段建立新规则；迁移未来例外并保留历史状态。修改整个系列：更新规则并预览受影响的例外与完成记录，不能不经说明地全部重置。

删除与撤销应恢复系列、例外、子任务状态和提醒计划。系统提醒登记失败不能导致业务任务恢复失败；失败状态进入提醒重试队列。

- 每月 29、30、31 的不足日期策略。旧数据保持月末补齐；新建时明确说明所选策略。
- 单次取消、改期、修改标题地点等，以及系列编辑三种范围。

执行顺序：先实现纯规则计算与边界用例，再落库，再做编辑选择和影响预览。
交付：结构化规则、稳定例外记录、修改范围弹窗。
验收：月底、闰年、间隔周、结束日期包含边界、次数计数与单次改期正确；过往完成记录不因编辑未来而丢失。
处理上限：为复杂规则设置可解释的计算上限，超过时报告；禁止无限循环。

### P1 07 年月周日与时间块

新增 YearCalendar、WeekCalendar、DayTimeline、TimelineLayoutService，共用 OccurrenceService。

执行顺序：

1. 年视图展示十二个月入口；月视图点击日期保留当前日期并进入周日尺度。
2. 周视图按日期列、时间行显示；日视图展开详细刻度。
3. 顶部区分全天事件与当天无具体时间的任务。
4. 有时间事件按真实起止占据区块，跨日事件拆分视觉片段。
5. 同时发生的事件使用列布局，不互相盖住文字。
6. 当前时间线只在包含今天的视图显示。后台恢复后按真实当前时刻更新。
7. 记住用户尺度，切换尺度与月份时保留选中日期。

布局算法约定：

- 时间占位使用真实分钟数；布局像素通过可配置的每分钟高度换算。
- 区间采用左闭右开；09:00 至 10:00 与 10:00 至 11:00 不构成时间冲突。
- 重叠事件先分成连通组，再按开始时间排序，以已结束列优先复用的方式分配列。
- 同组区块宽度按最大所需列数计算；结果需要稳定，避免刷新后左右跳动。
- 过短事件允许最小可见高度，但详情仍显示真实时间，不能以视觉高度改写时长。
- 时区变化、夏令时缺失或重复时刻必须使用支持时区的转换策略；不能给所有日期固定加 24 小时。

交付：四种尺度、详情联动、正确占位。
验收：7 至 8 点事件准确覆盖一小时；重叠三项均可点选；跨午夜不丢失；全天不挤入 00:00 时段。

### P1 08 日历拖动与时间调整

基于 P1 06 和 P1 07 进行。

执行顺序：

1. 长按空白时间格创建；长按区块进入拖动，避免普通滚动误触。
2. 拖动改开始时间，边缘拖动改时长。默认吸附 15 分钟，设置可选择 5 分钟。
3. 滚动到边缘时平稳自动滚动，并处理取消、越界和手势中断。
4. 移动重复事件先选择编辑范围；冲突出现时预览，不自动挤走其他固定事件。
5. 提交时事务写入；失败恢复原位置；成功提供撤销。
6. 日历和待办都立即反映新时间。

交付：可取消、可撤销的时间调整。
验收：只点不移动不会改时间；取消不落库；单次移动不改变整个系列；冲突提示使用真实时间区间。

### P1 09 ICS 与桌面迁移完善

升级 IcsService、BackupService、desktop-transfer，并新增导入来源管理。

执行顺序：

1. 保留折行、转义、UTC、本地浮动时间和时区校验。
2. 支持 VEVENT 的普通事件、全天、跨日及常见重复：FREQ、INTERVAL、COUNT、UNTIL、BYDAY、BYMONTHDAY、BYMONTH。
3. 支持 EXDATE、RDATE 和 RECURRENCE-ID 的常见取消改期情形。
4. 不支持的组合或未知时区单独报告，不能当成单次事件静默导入。
5. 以 sourceId 加 UID 加原始 recurrenceId 识别来源；不同文件来源的同名事件不随意合并。
6. SEQUENCE、更新时间和内容哈希帮助识别更新。相同内容再次导入不增加数据；有本地修改时提供保留本地或采用来源的预览。
7. 课表验收包含每周多天、隔周、学期结束、停课与换教室。
8. 桌面转换扩展明确能映射的规则；无法完整转换的系列继续报告，不能部分丢状态。
9. 新备份包含规则、单次例外、分类、来源和工具数据的格式扩展设计；第二三阶段继续加入字段。

交付：可用于常见课表的 ICS 导入、幂等更新和导入报告。
验收：同一文件导入两次任务数量不增加；修改某次课程正确显示；不支持的规则可追溯到事件标题与 UID。
范围说明：第一阶段不承诺完整 RFC 5545 的全部组合。导入支持表必须逐项维护，包括 VTODO 与自定义 VTIMEZONE 的支持或拒绝方式。

### P1 10 全局搜索与清单分类

升级已有关键词搜索，新增 SearchService、SearchPage 和分类清单管理。

执行顺序：

1. 搜索标题、备注、地点、标签与清单名称，显示任务和事件类型。
2. 可筛选完成状态、日期范围、优先级和来源；默认普通搜索不隐式改变首页数据。
3. 重复任务结果明确区分系列与发生项。默认展示系列和下一次；用户指定日期范围后显示该范围发生项，并限制结果上限。

## 7 第二阶段语音提醒与 AI

### P2 01 系统能力适配层

新增 interfaces 或 platform 目录，定义 SpeechAdapter、ReminderAdapter、CalendarAdapter、AiProvider 等边界。业务层不直接依赖权限弹窗、系统模型和网络回调。

执行顺序：读取本机 SDK 声明，查对应 API 26 官方文档，明确设备能力与权限，再写最小原生验证样例。样例在副本中运行，保留验证结果，不向正式任务制造无关数据。

交付：能力检测、可用性状态、取消和错误分类。
验收：接口不可用时仍能使用文字添加与本地任务；测试替身和正式实现切换明确。
注意：模拟接口仅用于开发测试，不能记录为真实语音或后台提醒验收。

### P2 02 原生语音快速添加

接入 CoreSpeechKit 的 speechRecognizer，申请麦克风权限并管理引擎生命周期。

执行顺序：

1. 用户点击麦克风后才请求必要授权，说明录音状态。
2. 显示准备、聆听、部分文字、识别完成、取消和失败状态。
3. 识别结果放入可编辑输入框，沿用 CaptureSheet。
4. 停止与取消后释放录音和引擎资源；页面离开、来电或切后台处理一致。
5. 识别没有文字时保持草稿，不创建空任务。
6. 设备模型不可用、网络异常或权限拒绝时提供文字输入方式，并显示真实原因。

交付：语音到文字再到草稿的完整流程。
验收：实际手机能识别中文；取消后麦克风停止；拒绝权限仍可使用；语音结果可改后保存。
范围：不要默认保证所有模拟器、设备或所有语言均支持离线识别。

### P2 03 系统提醒与登记一致性

新增 ReminderService、ReminderRepository 和同步队列。优先验证合适的原生代理提醒或 Calendar Kit 路径，选择依据记录在台账。

执行顺序：

1. 校验通知与能力权限，读取并展示系统允许状态。
2. 支持开始前、截止前和独立时刻提醒；为仅日期任务提供用户选择的提醒时间。
3. 发布成功保存系统 ID 与业务逻辑键。失败写入 pending 或 failed，不能显示“提醒已设置”。
4. 编辑、完成、删除、单次跳过、撤销和系列变更更新对应提醒。
5. 数据事务成功后通过持久同步队列调用系统接口；不把数据库事务和系统 API 假定成同一个原子操作。
6. 重启后对账，处理旧提醒、重复登记和中途失败。
7. 提醒点击进入正确任务或原始发生项，过期对象给出可解释结果。
8. 暂缓提醒更新原逻辑，避免同时保留旧新两条。

重复提醒不能通过无限预登记解决。必须按当前接口的权限、配额和重复能力设计；只预约有限窗口时，要明确窗口结束后和长时间不打开应用的行为。不能依赖应用被杀后仍会执行自己的定时器。

交付：系统登记、取消、对账与状态说明。
验收：前台 后台 进程终止 锁屏 重启分别验证；编辑后旧提醒不响；删除后不响；单次跳过不影响其他日期。
边界：普通通知优先级不等于能绕过勿扰或静音。紧急提醒的真实能力按目标设备和开放权限说明，不承诺未经验证的系统级特权。

### P2 04 AI 接入与安全配置

新增 AiClient、AiProviderAdapter、AiSettings 和 NetworkErrorMapper。参考桌面版 provider 适配思路，不复制 Windows 凭据或 requests 实现。

执行顺序：

1. 配置服务提供者、模型和接口地址，先完成连接测试。
2. 用户自带密钥通过鸿蒙支持的安全存储方式保存；读取本机可用接口后实现。
3. 普通日志、截图、Git 提交和 JSON 备份不包含密钥。
4. 明确离线规则、云端 AI 两种解析方式；未配置 AI 时离线方式继续可用。
5. 处理超时、限流、鉴权失败、取消、无效 JSON 和服务不兼容。
6. 用户主动启动 AI 时再发送本次输入及完成任务所需的最少上下文，设置提供发送范围说明。

交付：可替换服务适配、安全配置、失败恢复。
验收：无密钥、错误密钥、断网和取消均不生成任务；密钥不出现在备份和日志；旧任务可正常使用。

### P2 05 自然语言生成结构化草稿

新增 AiParseService，与离线解析共用 DraftValidator。

给 AI 的上下文包含当前日期、时间、时区、可选清单与标签。返回结构化草稿数组，包括标题、类型、安排、截止、地点、备注、预计用时、重复和提醒，以及每个推断的解释或待确认问题。

执行顺序：

1. 定义响应字段和限制，建立中文输入样例。
2. 保留用户原文，不直接执行模型返回的自由文本命令。
3. “明天”“下周一”等由统一日期解析器依据上下文校验。
4. 一段话含多件事时返回多张可编辑草稿。
5. 模型未明确获取的地点、起止和优先级可以留空；不能为了填字段而臆造。
6. “尽快”“有空”等模糊词形成建议或待确认项，不直接转成确定截止。
7. 校验日期、结束晚于开始、时区、重复结束和字段长度，非法项逐条解释。
8. 用户选择要保存的草稿后事务保存；若取消，不产生任务。
9. 保存时检测并发编辑或已存在相同草稿标识，避免连续点两次产生重复。

验收样例：

- “明天下午三点在图书馆和小李讨论项目，一个小时，提前十分钟提醒。”
- “周五前交报告，另外记得买牛奶，今天练习英语。”
- “每周一三五晚上七点跑步，持续半小时，到十二月底。”
- “有空整理照片。”
- “今天二十五点开会。”应给出无效时间，不能静默改成其他时刻。

交付：AI 输入到多条草稿的完整流程。
验收：用户确认前没有业务写入；原文可查看；不确定字段有明确标记；失败时可继续手动编辑。

### P2 06 AI 辅助排程与变更预览

新增 PlanningService 和 PlanValidator。第一版目标是提供用户可采用的时间建议。

执行顺序：

1. 读取用户工作时段、固定事件、任务截止、预计时长和明确优先级。
2. 缺少预计时长时要求用户补充或使用可见的默认假设。
3. 用确定性逻辑计算可用时间区间，固定事件和用户锁定任务不能被随意移动。
4. AI 提出任务顺序、时间段及理由；程序校验冲突、截止与可用时段。
5. 无法满足全部任务时指出无法安排的任务及原因，不伪造“全部安排完成”。
6. 展示前后差异、采用单项或整组、取消和撤销。
7. 采用前比较源数据 updatedAt 或版本号，数据已变化时重新计算，防止覆盖用户刚编辑的安排。
8. 采用只更新计划字段，不自动标记完成，不改变用户已明确的截止或优先级。

交付：可解释、可局部采用和可撤销的建议。
验收：固定课程不被移动；过量任务明确报告；取消无写入；采用时冲突校验有效；撤销恢复原安排和提醒计划。

### P2 07 系统能力与 AI 联合验收

执行完整链路：说一句话、修改识别文本、AI 分拆、核对地点与时间、保存、退出应用、系统提醒、点击进入、完成后取消后续无效提醒。

还要验证：语音有结果但 AI 超时；AI 有草稿但保存失败；任务保存成功但提醒登记失败；用户关闭 AI 或撤回麦克风授权；重复单次改期后提醒更新。

交付：实机记录、支持设备与权限说明、失败场景记录、0.7.0 源码与归档。
通过条件：不得把模拟器或测试替身结果冒充真机后台能力。业务数据保存状态与提醒成功状态分别展示。

## 8 第三阶段综合工具与产品验收

### P3 01 模块注册与可选入口

新增 FeatureSettings、FeatureRegistry 或等价简单结构，集中管理模块开关与入口。

默认启用任务与日历。专注、习惯、倒数日和 AI 按用户偏好显示。四个底部栏目保持稳定，可选工具从相关页面卡片或设置中的功能入口进入。

交付：简洁与完整预设、独立模块开关。
验收：隐藏后数据仍在；重新启用可恢复；相关系统提醒的执行状态不因隐藏而被隐式改变。

### P3 02 番茄钟与专注记录

新增 FocusSession 模型、FocusRepository、PomodoroService 和专注页面。不要与现有用于首页概览的 FocusService 混淆命名。

执行顺序：

1. 支持工作时长、短休息、长休息和循环次数设置。
2. 开始可关联任务，关联是可选项；专注结束不自动完成整个任务。
3. 保存实际开始、预期结束、暂停区间和状态；倒计时显示由真实时刻推导。
4. 切后台或重启后重建状态，不用每秒减一作为唯一真相。
5. 到时提醒复用第二阶段的系统能力；不支持时显示明确能力边界。
6. 支持暂停、继续、放弃和历史统计，统计有效时长而非计划时长。

交付：能恢复的计时与专注记录。
验收：后台十分钟后剩余时间正确；暂停不计有效专注；修改手机时间后的行为可解释；关联任务删除后历史仍能阅读。

### P3 03 习惯打卡

新增 Habit、HabitOccurrence、HabitRepository 和 HabitService。

执行顺序：

1. 支持每天、指定星期和每周次数目标，规则与普通待办重复区分。
2. 一个日期允许明确的一次或数次目标，记录稳定 ID 防止双击重复。
3. 支持今天打卡、取消和补打，并标注补打日期。
4. 连续天数只根据应打卡日期计算，未要求打卡的星期不打断。
5. 独立设置提醒时间，可关闭；复用提醒服务。
6. 今日概览可以显示习惯摘要，但不混入待办完成分母。

交付：目标、打卡、历史、统计与提醒。
验收：周末休息不打断工作日习惯；跨午夜使用明确本地日期；取消补打正确重算；重复点按不增加多条记录。

### P3 04 倒数日与纪念日

新增 Countdown、CountdownRepository、AnniversaryService 和对应页面。

执行顺序：

1. 支持未来倒数与过去累计，明确是否包含当天，默认按日期差显示。
2. 纪念日可按年重复，处理闰年和 2 月 29 日策略。
3. 分类、排序、置顶、删除与撤销。
4. 允许展示在今天的可选卡片，默认数量有限，更多进入独立列表。
5. 可设提前提醒，复用系统提醒能力。
6. 第一版以公历为准；农历若没有已验证转换能力，必须作为未支持项，不自行用固定日期冒充。

交付：日期工具、年度发生项与提醒。
验收：今天显示 0 天；月末和闰年正确；本地午夜更新；未来和过去方向正确。

### P3 05 备份与导入的全产品覆盖

在第一阶段备份结构上补入专注、习惯、倒数日、模块偏好和 AI 非敏感配置。提醒保存逻辑计划，不直接恢复旧设备的 systemId 或密钥。

执行顺序：定义格式扩展、兼容读取、预览数量与冲突、事务导入、恢复后重新登记提醒。导入失败不能留下半个系列或半套习惯记录。

交付：完整备份与有说明的恢复。
验收：新设备恢复数据一致，旧备份仍可读取，提醒不重复登记，密钥缺失时 AI 显示待配置。

### P3 06 性能可访问性与设计验收

- 测试小屏、大字体、横屏与可获得的大屏设备；当前重点仍是手机。

交付：设计截图集、可访问性与性能记录。
验收：主要功能无需精确点击小图标也可完成；大字体不遮挡保存；低材质能力设备内容仍清楚；长列表可用。

### P3 07 最终回归与发布材料

交付完整源码、README、运行说明、版本说明、已知限制、Demo 脚本、演示视频和 PPT 或 PDF 汇报材料。汇报需要解释架构、数据持久化、重复发生项、AI 草稿校验和提醒一致性。

## 10 开发期间的检查与故障处理

### 10 1 每个工作包的固定流程

1. 检查 PROGRESS.md 的当前任务、依赖和未解决问题。
2. 读取涉及文件，写明当前行为与目标行为。
3. 先完成最小的数据或业务改动，运行适当检查。
4. 接入界面，构建并在原生设备检查目标交互。
5. 记录改动、结果、证据路径、剩余限制和下一步。
6. 只有验收通过才把工作包设为 verified；有代码但未设备验收设为 implemented_unverified。
7. 下一工作包根据依赖顺序进行，不把多个未知问题一次堆积。

### 10 2 本机基础命令

在实际采用的桌面副本目录执行，不在原项目执行。

~~~powershell
Set-Location -LiteralPath 'C:\Users\Lenovo\Desktop\taiplan-harmony-test'

& 'D:\Program Files\Huawei\DevEco Studio\tools\node\node.exe' --test tests/core.test.cjs

$env:DEVECO_SDK_HOME='D:\Program Files\Huawei\DevEco Studio\sdk'
$env:JAVA_HOME='D:\Program Files\Huawei\DevEco Studio\jbr'
$env:Path='D:\Program Files\Huawei\DevEco Studio\tools\node;'+$env:Path

& 'D:\Program Files\Huawei\DevEco Studio\tools\ohpm\bin\ohpm.bat' install
& 'D:\Program Files\Huawei\DevEco Studio\tools\hvigor\bin\hvigorw.bat' --mode module -p product=default -p module=entry@default assembleHap --no-daemon

$taskHdc='D:\Program Files\Huawei\DevEco Studio\sdk\default\openharmony\toolchains\hdc.exe'
& $taskHdc list targets
~~~

依赖安装仅在包配置变更或依赖缺失时执行。不能每个 UI 改动都重复安装。设备地址以 list targets 实际返回为准，不固定假设 127.0.0.1:5555。

覆盖安装和启动示例：

~~~powershell
$taskDevice='替换为本次实际设备地址'
& $taskHdc -t $taskDevice install -r entry\build\default\outputs\default\entry-default-unsigned.hap
& $taskHdc -t $taskDevice shell aa start -a EntryAbility -b com.taiwoo.taiplan
~~~

真机签名路径以本次 DevEco 配置为准。新的测试文件加入相应测试入口后再运行完整命令；不能只运行旧 core.test.cjs 而遗漏新增服务。

### 10 3 错误定位顺序

| 问题 | 首先检查 | 修复后验证 |
| --- | --- | --- |
| 构建失败 | 第一条编译错误 SDK 与 ArkTS 类型 | 相关代码检查 完整构建 |
| 运行白屏 | Ability 生命周期和首屏异常 日志 | 启动 切栏目 重启 |
| 列表不刷新 | 状态所有权 引用更新 组件复用键 | 连续完成 编辑 删除 撤销 |
| 数据丢失 | 迁移事务 日志 备份 表结构 | 旧库升级 双重启 回滚 |
| 时间差一天 | 日期字符串与时间戳混用 时区 | 本地午夜 UTC DST 样例 |
| 单次改期影响系列 | 原始发生项身份 override 写入 | 三种编辑范围及历史完成 |
| 提醒不触发 | 系统授权 能力配额 登记状态 设备限制 | 前台 后台 退出 重启 |
| ICS 重复或错误 | source UID recurrenceId 时区 RRULE | 幂等导入与差异预览 |
| AI 内容异常 | 原响应 结构校验 日期上下文 | 拒绝无效草稿与可编辑恢复 |
| 手势误触 | 滚动与长按状态 吸附 取消流程 | 轻点 滚动 拖动 手势中断 |

禁止通过清空数据库、删除原缓存、隐藏异常或伪造成功状态解决问题。系统能力暂时不可用时保留可用功能，准确说明阻塞点和已完成范围。

## 11 版本归档和发布规则

1. 历史 archive/v0.2.0 至 archive/v0.5.0 不移动、不覆盖。
2. 开发阶段使用 development/v0.6.0 等分支，内部检查点做小提交，每条提交说明行为与验证。
3. 阶段验收通过后更新应用版本号、README、变更记录和 PROGRESS.md。
4. main 只放已验收源码。不能把一个未验证的大阶段直接推成稳定版。
5. 有标签权限和可用工具时建立 v0.6.0 等标签；只有分支接口时建立 archive/v0.6.0 并记录完整 SHA。没有创建标签就不能说已打标签。
6. 源码不混入 .hvigor、oh_modules、build、证书、密钥、用户数据库、个人导入文件和测试布局。
7. HAP 作为独立发布产物归档，明确版本、提交、SDK、签名类型、设备用途和 SHA-256。
8. 归档至少包含 SOURCE_MANIFEST.json、CHANGELOG.md、README、验收记录、已知问题和相应 HAP。
9. 构建完成后源码又有修改，必须重新构建相关产物，不能给新源码配旧 HAP。
10. 上传后回读远端版本号、分支头和关键文件，核对产物哈希。不以“工具调用成功”代替最终验证。
11. 本轮只输出计划和台账；后续真正开发时，GitHub 上传与发布范围依照当时用户授权执行。

## 12 进度状态和交接格式

状态含义：

| 状态 | 含义 |
| --- | --- |
| planned | 已定义，尚未开始 |
| in_progress | 正在开发，尚未完成 |
| implemented_unverified | 代码已写，验收未结束 |
| verified | 工作包验收与证据齐全 |
| blocked | 有明确外部条件或待决定事项，写清可继续的工作 |
| deferred | 用户或范围明确暂缓，并记录原因 |

工作包达到 verified 才能计入已验收进度。阶段内任务不是等量工作，不用“11 项做了 5 项”直接宣称整体完成 45%。阶段状态由退出条件决定。

接班 AI 开始执行：

1. 读本计划、PROGRESS.md、当前工作目录的 README 和实际适用的 AGENTS.md。
2. 以用户最新指令为准，不把历史文件里的开发建议当成额外授权。
3. 检查当前文件与记录是否一致，特别是未提交改动和数据库版本。
4. 继续正在执行的工作包；已 verified 的工作包不重新实现。
5. 先复现记录里的阻塞问题，再决定修改，不凭旧截图猜测当前状态。

## 14 近期考核与完整产品路线

用户提供的考核时间是 10 月 11 日下午 2 点 30 分，计划制定时间是 10 月 10 日。三个阶段描述完整产品开发范围，不构成一天完成全部功能的工期承诺。

如果仍以此次考核为最近目标，应保留已经可运行的 0.5.0，优先交付第一阶段里已实际通过验收的体验改进。大数据迁移或系统能力未验收前，不替换稳定演示版本。汇报准确说明已经完成和后续规划，不能展示未实现功能作为现场可用能力。
