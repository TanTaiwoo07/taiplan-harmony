# 本机演示与答辩

建议 3～5 分钟。已有用户任务不删除、不批量改写；演示创建自己的「演示_」事项，结束后删除。

1. 打开 API 26 模拟器，双击 Start-TaiPlan.cmd。首页说明今天完成分母只包含任务，事件不勾选。
2. 指出紧急徽标、具体截止时间、逾期计时。说明优先级与分类用途不同。
3. 记一件事输入「演示_买牛奶」，收集无日期任务。待办收集箱看到它，点击编辑安排今天，返回可完成/取消。
4. 日历年 → 月 → 周 → 日。解释事件区间覆盖相应刻度、跨午夜拆分、无时间事项另放日期区。
5. 重复任务点击编辑选择仅本次，解释原日期身份；有历史的复杂变更保护性拒绝。
6. 智能输入输入「明天下午三点讨论项目，一个小时；今天练习英语」，离线识别两张草稿；核对后可保存。不要演示未配置 AI 或假装语音成功。
7. 设置中完整预设，打开工具：番茄钟暂停与恢复；习惯打卡及撤销；倒数日今天 0 天；简洁预设隐藏工具但数据不删。
8. 展示备份/恢复预览、深浅色；退出重开确认持久化。说明设备提醒发布限制，不宣称未成功能力。

答辩重点：

- 为什么选 ArkTS/ArkUI：原生组件和系统能力，数据与业务分层，不靠 Web 容器。
- 为什么安排与截止分开：安排今天不代表午夜逾期，无日期收集也不是延迟任务。
- 重复任务怎样存：系列模板 + 原日期身份 + 完成/跳过状态 + 单次覆盖，不展开所有未来日程落库。
- AI 如何可靠：结构化输出经过日期/时间/规则/长度校验，确认前没有写入；密钥用安全资产存储。
- 保存和提醒为什么分开：系统权限、配额、设备能力都能让提醒登记失败；业务数据仍保留并显示失败。
- 计时为什么可恢复：保存实际时刻和累计秒数，界面推导剩余时间，不以每秒减一为唯一事实。
- 备份为何事务：任务、例外、工具和偏好要整体成功，否则回滚，避免半恢复。
- 测试证明什么：118 项业务/SQLite/替身回归 + 原生点击证据，不等同于所有真机能力通过。

随包静音演示使用模拟器实际画面，约一秒采样一次，适合观察功能路线；不是动画流畅度评测，也没有后台通知成功画面。
